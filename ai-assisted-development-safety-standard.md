# AI-Assisted Development Safety Standard

## Purpose

This standard defines how generative AI may be used during development while maintaining security and reliability.

AI is treated as a productivity tool rather than a trusted source of production code.


## Core Principle

AI output is untrusted code.

Code generated by AI must pass automated verification before being accepted.


## Approved Verification Methods

Projects using AI-assisted development must use reputable tooling to review and validate code.

Examples include:

- static analysis tools
- CodeQL analysis
- compiler warnings treated as errors
- sanitizer builds (ASan, UBSan)
- dependency vulnerability scanning
- automated tests


## Security Issue Handling

All automated review tools must be monitored for issues.

| Severity | Required Action |
|---|---|
| High / Critical | Must be investigated and resolved before release |
| Medium | Should be reviewed and addressed where practical |
| Low | May be tracked for improvement |


## Acceptable Uses of AI

AI may be used for:

- drafting boilerplate code
- generating documentation
- suggesting implementation approaches
- refactoring code
- explaining complex behaviour


## Prohibited Uses

AI must not be used to:

- bypass automated verification tools
- automatically commit code without checks
- ignore High or Critical security findings


## Testing Requirements

AI-generated code must pass project verification steps including:

- successful compilation
- static analysis checks
- sanitizer builds where applicable
- automated tests


## Compliance Checklist

Before merging AI-assisted code:

- [ ] automated analysis completed
- [ ] security tools reviewed
- [ ] no High or Critical issues unresolved
- [ ] tests pass successfully
